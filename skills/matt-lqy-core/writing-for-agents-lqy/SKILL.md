# 为 Agent 写作

让 agent 稳定遵循同一过程，而不是强求每次产生相同输出。适用于 skill、常驻说明和按引用加载的文档；编写 skill 时再读 [SKILL-MECHANICS.md](SKILL-MECHANICS.md)。

## Context pointer

**Context pointer** 是常驻上下文中的引用：它说明外部材料是什么、什么情况下该读取。skill description 与 AGENTS.md 的文档指针属于同一对象。

先改善触发措辞，再考虑把正文常驻加载：概念词前置，每个真实分支一个触发，不用多个同义词重复同一分支。pointer 每轮都付 Token 成本，剪裁应比正文更严格。

## 两种成本

- **Context load**：常驻说明、描述每轮占用上下文与注意力。
- **Cognitive load**：人需要记住有哪些文档、何时使用。保留需要人判断的入口，移除不需要人的记忆负担。

通过 pointer 按需加载正文，避免把所有参考材料压进常驻文件。

## 信息层级与组织

内容分为有顺序的 **steps** 与按需查阅的 **reference**，不强制每份文档同时具备两者。

1. 正文步骤：当前应该做什么。
2. 正文参考：各分支共同需要的规则。
3. 外部参考：仅某些分支需要的细节，放同目录 supporting file 并提供明确 pointer。

**Progressive disclosure**：共同需要的内容内联，分支特有内容下移。下移太多会藏掉必需规则；保留太多会淹没步骤。

**Co-location**：同一概念的定义、规则与例外放一起，不散落到多个标题。**Sprawl** 是即使每句都有用，文档仍过长；按分支或序列划分，不把它切成许多浅包装。

## 完成标准

每个步骤的完成条件要可观察、覆盖必要行为。先收紧模糊条件，避免后续步骤诱导提前宣布完成；只有真实的上下文边界才能把后续内容移出视野，内联调用不能清空上下文。

按步骤拆分只有在完成条件模糊且已观察到抢跑时才值得。不是每个阶段都需要新 skill、handoff 或 subagent。

## Leading word

使用模型已理解且项目反复使用的紧凑概念词，例如 seam、tracer bullet、frontier。定义后重复词，不重复整段含义；不为显得专业创造新术语。

优先描述目标行为。禁止规则只用于不能正向表达的真实边界，并配上应该做什么；不要用无穷的禁止清单替代清晰合同。

## 删减

- **Single source of truth**：一个含义在一个权威位置；引用它，不复制它。
- **Cache**：配置、目录、package.json 和 `--help` 已是事实来源。简单查询能得到的事实不再抄一份；文档保存查不到的约定、理由和 gotcha。昂贵查询确需缓存时说明来源。
- **Relevance**：删除与任务无关或已过时的层积，不因“留着安全”不断加说明。
- **No-op**：不改变 agent 行为的句子直接删除。判断是否无效依赖当前模型与真实运行证据，不靠争论。

保留已有公开合同、项目数据和必要边界。文档精简不是授权修改项目结构、删除旧个人 skill 或增加新的安全流程。
