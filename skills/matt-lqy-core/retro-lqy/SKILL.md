# 会话复盘

用户明确请求复盘后才运行。默认复盘当前会话；指定其它会话时，只读取对应且可访问的记录。Pi / Codex 日志路径以当前环境为准，不假设 Claude 会话格式，也不扫描无关项目。

先读取并执行 `writing-for-agents-lqy` 的 `SKILL.md`。用一手会话记录和仓库现有约定支持结论；日志不可访问就说明限制，不编造会话事实。

## 查什么

- **导航**：反复找同一事实、隐藏依赖、找不到文档。优先改善已有导航 pointer。
- **检查**：先读项目已有 check / lint / test 与 CI。检查存在但未接入是问题，不另造一套。机械错误建议现有工具可执行的检查；判断问题才建议 review standards。
- **规则**：指令是否重复、失效、常驻过多，或让实施 agent 被迫承担本属 review 的工作。
- **工具成本**：重复查询、输出过大、失败重试、为浅任务增加 agent / harness。
- **信息**：确有缺失的运行信号或访问条件；只建议所需范围，不默认扩大凭据、数据库或生产访问权限。

## 输出与边界

按影响排序，每项写：会话证据、实际损失、最小建议、取舍和是否需要人决定。没有可靠证据就不列为确定问题。

复盘只提出建议。未经用户选择，不改代码、配置、AGENTS.md、CI、安装副本或业务数据，不安装工具，不启动 Ralph、subagent 调度或定时任务。不要把每次开发都变成环境整改。

凭据只在展示副本中隐藏；原始日志、配置、fixture 和真实复现输入保留。隐藏后不足以说明问题，就向用户说明限制。

Ralph 仍是批量实施入口：用户批准且已明确的改进可以另行按单 Ticket 工作流实施；复盘本身不直接将猜测发布为 ready-for-agent，也不自动消费这些建议。
