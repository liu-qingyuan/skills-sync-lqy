# clean

在不改变可观察行为、公开合同、必要数据和安全约束的前提下，清除偶然复杂性。用户明确授权改变行为时，以双方确认的新合同为准。

## 适用场景

- 代码能工作，但臃肿、重复、难读或抽象过度
- 实现中存在死代码、临时 workaround、静默 fallback、吞错或多条重复路径
- Module 太浅、Interface 泄漏 Implementation 知识，或同一决策散落在多个位置
- 文档、skill、配置、界面或流程包含重复结构、无效说明或无用选项
- 用户给出文件列表，要求只清理这些文件

## 决策依据

- 开始前读取并遵循 `$simple`，按“删除、复用、最小新增”的顺序选择第一个完整解。
- 只有候选改动涉及 Module、Interface、Implementation、Seam、Adapter、Depth 或 Information Leakage 时，才读取并遵循 `$codebase-design-lqy`；不要为清理制造假想接缝或浅包装层。
- 两个 skill 提供判断标准，不替代当前代码、测试、调用链和 diff 证据。

## 范围与停止条件

- 调用方给出文件列表时，严格限制在该列表内；否则从请求和真实调用链确定最小范围，并在动手前说明。
- 不顺手处理范围外问题。只记录与当前任务直接相关但有意推迟的风险。
- 如果清理必须改变可观察行为、公开合同、依赖或范围外文件，停止并向用户确认。
- 不新增依赖、配置、Interface、Adapter 或扩展点，除非当前需求证明它们必要。

## 流程

1. **锁定行为与范围**
   - 检查目标文件、真实调用链、现有 diff 和项目约定。
   - 明确不得改变的行为、准备移除的异味和编辑范围。
   - 先运行针对性回归测试；行为缺少保护时，添加所需的最小测试。文档、skill 和配置改动使用相应 validator 或 smoke check。

2. **按证据定位偶然复杂性**
   - **死代码与重复**：未使用代码、不可达分支、过时标志、复制粘贴逻辑和重复事实来源。
   - **无意义间接层**：纯转发 wrapper、单次使用 helper、推测性 options、registry、factory、Interface 或 Adapter。
   - **错误与回退**：吞错、静默默认值、绕过主要合同、未经测试的替代路径和宽泛兼容 shim。
   - **设计问题**：浅 Module、错误位置的 Seam、Information Leakage、调用方 glue code，以及按执行顺序而非共享知识拆分的 Module。
   - **内容与界面噪声**：重复标题或说明、无意义徽章和装饰、机械网格、无用配置及手工步骤；保留有明确品牌、设计系统、可访问性或产品语境依据的内容。

3. **选择最小完整修复**
   - 优先修复根因或共享路径，然后删除死代码、合并同一知识的重复实现并收紧命名和错误合同。
   - 只删除偶然复杂性；不要用更深嵌套、更高信息密度或更差可调试性换取更少行数。
   - 涉及设计时，让一个 Module 拥有相关知识，通过小而稳定的 Interface 隐藏 Implementation；测试该 Interface，不公开内部机制。
   - 将回退分为两类：掩盖错误、绕过合同或缺少测试的回退应删除或改为显式失败；位于真实外部、版本兼容或故障安全接缝上，保留失败证据且主路径和回退路径都有测试的回退可以保留。

4. **逐类执行**
   - 每轮只处理一种异味，完成后运行最相关的验证。
   - 不把无关重构并入同一组编辑，也不在旧路径旁叠加一条“更干净”的重复路径。
   - 新证据表明计划不成立时，更新计划；只有范围或行为会实质改变时才询问用户。

5. **运行质量门禁**
   - 运行项目已有的相关回归测试、lint、typecheck、构建、合同测试和静态或安全检查。
   - 运行 `git diff --check`，确认 diff 最小、范围正确且没有调试残留。
   - 无法运行某项检查时，说明原因和替代证据，不声称该项通过。

## 输出

只报告完成判断所需的信息：

- 范围和变更文件
- 删除或简化了什么
- 行为由哪些测试或证据锁定
- 设计或回退决策（如有）
- 实际运行的检查及结果
- 剩余风险或明确推迟的事项
