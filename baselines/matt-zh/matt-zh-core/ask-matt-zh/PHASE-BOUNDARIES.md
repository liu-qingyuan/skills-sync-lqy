# 阶段边界

**阶段**是一次会话中的一段工作：追问、实现、QA。定义刻意保持模糊：当你觉得“好了，这件事做完了”，一个阶段就结束了。

**阶段边界**是两段工作的间隙，只有这里才需要作出下述选择。阶段中途没有这个决策：继续，或者将剩余工作拆给 subagent。中途压缩上下文会让 Agent 失去思路。

## 五个选择

| 选项 | 作用 |
| --- | --- |
| **继续** | 留在当前会话，完全不切换上下文。 |
| **`/clear`** | 清空上下文，从零开始。 |
| **`/handoff-zh`** | 写可携带的 Markdown 文件，用它在其他地方开启会话。 |
| **Subagent** | 把任务交给独立上下文，接收其报告。 |
| **`/compact`** | 压缩当前上下文，用摘要开启新会话。 |

## 决策树

在阶段边界自上而下判断，第一个回答“是”的分支胜出。

**1. 能在当前会话继续吗？**若下一阶段需要本阶段作为**第一手资料**，或剩余 [高效上下文区](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（约 150k Token）足以容纳下一阶段，答案就是“能”。追问 → 实现是典型情形：实现需要逐字保留推理过程，而不只是摘要。继续既不增加成本也不丢失信息，因此先排除它再考虑其他选项。

**2. 当前上下文对下一阶段无关吗？**探索、决策和死胡同都可以丢弃吗？若是，就 **`/clear`**。它成本最低：立即返还完整窗口，旧会话仍可恢复，并非终止。错误清空*相关*上下文的代价是单向的：失去构建背后的**原因**，重读 diff 也找不回来。

**3. 需要交接吗？**`/handoff-zh` 的适用面很窄，仅当：

- 切换到**另一套 Agent 运行环境**（如 Claude → Codex）；
- 移动到**另一个目录**或仓库；
- 把工作交给**同事**；
- 在**阶段中途**分叉一个旁支任务，避免打断当前工作。

以上就是全部条件。`/handoff-zh` 的价值是**可携带性**：文件能够移动。如果没有东西要移动，就不需要它。

**4. 任务可以独立完成吗？**任务是否足够聚焦，能在无人引导时运行？若是，交给 **subagent**，保持当前会话原状。自动 review 是典型情况：Agent 读 diff 并报告，期间无需你参与。

**5. 否则使用 `/compact`。**上下文仍相关，Agent 环境和目录没变，且你需要留在循环中：决策树常常会落到这里。附带指令（如 `/compact 接下来要对这块做 QA`），使摘要保留下一阶段需要的内容。

`/compact` 是**最后的默认选项，不是第一个选择**。之所以在底部，是因为前面四个问题的选择更便宜或更精准。若一开始就压缩，失败模式是：新会话对某个被摘要压扁的决策信心十足，却理解错了。

## 第一手与第二手资料

除了**继续**，每个选项都会将**第一手资料**转换成**第二手资料**：实际发生的会话变成其摘要。取舍始终如此：

| 资料 | 信息 | 噪声 | 后续空间 |
| --- | --- | --- | --- |
| 第一手（继续） | 完整 | 多 | 少 |
| 第二手（`/compact`、`/handoff-zh`） | 有损 | 少 | 多 |

这正是问题 1 放在最前面的原因。只有继续的代价高于保留原文的价值时，才承担信息损失。

## 这些是判断题

问题不是客观算法：每一步都需要判断，同一个边界在不同日子也可能作出不同选择。价值在于**依次**提问，并且在边界而非工作中途提问。
