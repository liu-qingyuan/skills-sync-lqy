# 向导

**向导**是一段 bash 脚本，逐步引导人完成手工操作，避免每次都亲自梳理步骤或向 AI 重新解释。它打开 URL，明确告诉用户点哪里、复制什么，收集值并写入正确位置（`.env`、GitHub secrets），每阶段请求确认并显示剩余阶段数。它可配置第三方服务、运行一次性迁移，或将项目从一个状态切换至另一个状态。

[template.sh](template.sh) 已经解决体验问题：阶段进度、确认关卡、跨平台打开 URL（含 WSL）、隐藏式 secret 输入、幂等 `.env` 更新、`gh secret`/`gh variable` 写入与结束总结。**你的工作仅是确定流程范围并编写阶段。** `STAGES` 标记以上的库在所有向导中完全相同；一致性正是目的，不要手工编辑该区域。

向导默认是临时产物：为单次执行创建，保存到临时目录或 `scripts/` 路径，任务完成后删除。仅当用户希望仓库保留可重复的配置流程时才提交。

## 流程

### 1. 确定流程范围

找出人必须执行的每个步骤，以及途中收集的每个值。先阅读仓库，不要直接问用户：

- 配置：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置和 `.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用都是向导必须提供的值）。
- 迁移或过渡：当前状态、目标状态以及之间不可逆的操作。

随后展示按顺序排列的阶段以及各自生成的值，请用户确认；用户可以增删或调整顺序。

**完成条件：**每个阶段都有名称和顺序；对每个收集到的值，已知 (a) 人从哪里获取，(b) 写入哪里（`.env`、GitHub secret、两处或不写入——有的阶段只有操作），(c) 它是 secret（隐藏输入）还是公开值。

### 2. 绘制每阶段的操作路径

每个阶段都写清人如何操作：打开哪个 URL、在其中做什么、值出现在哪里、对应哪个变量。例如“Dashboard → Developers → API keys → Reveal test key → 复制”。如果不知道当前 UI 或确切命令，就直说并询问用户或查阅文档；不要编造可能不存在的步骤。

**完成条件：**每阶段都有具体操作说明，陌生人也能照做。

### 3. 编写向导

将 `template.sh` 复制到目标路径。用按依赖顺序排列的 `stage` 代替示例阶段，每一步一个 `stage`。使用库提供的 `stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。将 `TOTAL_STAGES` 设为编写的阶段数量。

维持模板标准：获取值前打开 URL，机密值用 `ask_secret`，持久化值都用 `write_env`，仅对 CI 实际需要的值使用 `set_secret`，不可逆操作前先 `confirm`。每个 `stage` 都会清屏，只显示当前步骤；每阶段聚焦一项任务，避免用户需要的信息被滚动出屏幕。不要动标记以上的库。

### 4. 验证并交接

- 执行 `bash -n <script>`；有 `shellcheck` 时也执行。
- 执行 `chmod +x <script>`。
- 不要亲自端到端运行：它会打开浏览器并等待人的输入。改为静态检查：步骤 1 的每个值都被收集并写入约定位置，每个 `set_secret` 名称都与 CI 的 `secrets.*` 引用完全一致。
- 告诉用户运行方法。如果它是可重复的配置流程，提交脚本并在 README 中添加链接，让下次使用者运行脚本而非询问 AI。
