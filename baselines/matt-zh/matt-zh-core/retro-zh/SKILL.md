用户请求做**复盘**。你应建议如何改善编码 Agent 的**环境**，以提升之后的执行效果。

## 步骤

1. 调用 Skill 工具并指定 `writing-for-agents-zh`，获取写作风格指南。

2. 阅读用户指定会话的第一手资料，可能需要搜索本机的会话日志。若用户未指定，默认为当前会话。

3. 从以下类别寻找改进候选：

- **导航**：Agent 能否轻松找到正确文件？文件间是否存在隐藏依赖？**导航指针**是否有帮助？_适用时机_：会话花了很长时间寻找信息。
- **自动检查**：lint、类型检查、测试或文件系统 linter 是否能捕捉 Agent 犯的错误？先阅读仓库自己的检查命令（`package.json` / 构建工具的 `lint`/`check` 脚本、CI workflow），因此已有但未接入或静默失效的检查才是发现，而不是重新造一个。仓库完全没有**护栏**（没有 pre-commit hook，也没有 CI job 执行 lint/typecheck/test 命令），本身就是一项发现：没有 lint 不是中性的默认状态，而是持续错失的机会。_适用时机_：自动检查可捕捉某项错误，或仓库完全没有护栏。
- **编码标准**：是否要给 **reviewer Agent** 添加规则？是否应删除或明确已有规则？先分类违规：**机械性**的（固定语法模式、禁用 API、import 形态、文件位置规则）必须用确定性检查——仓库现有 linter 的自定义规则、新 pre-commit hook 或新 CI job，选择在当前语言和护栏下成本最低的一种。默认构建检查，而不是写规则。`CODING_STANDARDS.md` 只用于真正需要**判断**的事项（跨文件一致性、与周围风格吻合、其他护栏无法替代的判断）。_适用时机_：reviewer Agent 漏掉了一个错误。
- **全局 AGENTS.md**：是否有指引应转移到编码标准（或自动检查）？_适用时机_：仓库或用户全局范围的 AGENTS.md 特别庞大。
- **工具经济性**：有没有可以简化的昂贵工具调用？某个自定义 CLI 或 MCP 是否特别浪费 Token？_适用时机_：Agent 发起了昂贵调用。
- **无效指令**：寻找引导文件中不改变 Agent 行为的指令。_适用时机_：引导文件庞大难用。
- **信息获取**：能否增加 Agent 的信息获取渠道，例如保存开发服务器日志，或提供第三方服务的只读访问权限？_适用时机_：Agent 缺少关键资料。

4. 按严重程度向用户展示候选。

## 参考

### 实现与 review

所有工作都经历实现和 review 两阶段。实现 Agent 的**上下文压力**最大：负责探索、写代码和调试失败。

review Agent 的上下文压力最小：它拿到 diff，通常无需探索，也往往不用写代码或调试。

因此应由 review Agent 负责施加编码标准，而不是实现 Agent。

### 文件

仓库中可能有这些文件：

- `CLAUDE.md`/`AGENTS.md`：自动进入在仓库工作的 Agent 上下文。要极度克制使用，通常只放指向其他文件的**导航指针**。
- `CODING_STANDARDS.md`：review 时阅读，而不是实现时。若标准超过 1,000 行，添加指向 docs 目录的**导航指针**。
- Docs：作为其他文件通过指针访问的参考。写新文档前先查已有文档。
- Skills：用作文档（因为 description 会进入 Agent 的上下文），或用户手动触发的命令。遵循 `writing-for-agents-zh` 的建议。
