这是为 Agent 撰写任何文档的参考：Skill、`AGENTS.md` / `CLAUDE.md`、通过指针访问的文档。包装方式不同，写作原则却相同：相同的杠杆使每次执行可预测，因为 Agent 每次遵循相同的*过程*，而不是产出完全相同的结果。

若编写的是 Skill，请阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式的选择以及路由 Skill。

## 上下文指针

**上下文指针**是留在 Agent 上下文中的引用：它命名上下文之外的材料，并编码触发访问该材料的条件。Skill 的 description 是一个指针；`AGENTS.md` 中指向文档的一行也是同一类对象。决定 Agent 何时、能否可靠访问材料的是指针的*措辞*，而非目标。必须阅读的目标若藏在弱指针背后，会造成执行差异：先强化措辞，只有强化仍无效时才将内容内联。

指针有两项任务：说明材料是什么，列出应触发访问的各个**分支**（分支是文档处理的不同情形，所以不同执行会走不同路径）。常驻指针的每个词在每轮都会花费 Token，因此比正文更需要删减：

- **把引导词放在前面**：指针在这里发挥触发作用。
- **每个分支一个触发条件。**将同一分支换个名字的同义词只是写了两次；合并它们，只保留真正不同的分支。
- **删除正文已经承载的身份说明。**

## 两类负担

每新增一个文档或指针，都会消耗以下两类预算之一：

- **上下文负担**：常驻材料占用 Agent 窗口的成本，如 `AGENTS.md` 的一行、Skill description；无论是否触发，都会持续消耗 Token 和注意力。
- **认知负担**：人需要记住有哪些文档、何时去找它们的成本。人是索引。这不是必须最小化的成本，而是人的自主判断所付出的代价；在人类判断重要时投入，在不重要时削减。

只通过指针访问的材料免去正文的常驻上下文成本，但仍需付出指针本身的成本；完全没有指针的材料则完全依靠人的认知负担。

## 信息层级

文档由两类内容构成：**步骤**（Agent 有序执行的动作）和**参考**（按需查阅的定义、规则与事实）。两者可自由组合：全是步骤（操作配方）、全是参考（review 规则、本 Skill），或二者兼有。核心决定是将每一部分放在**信息层级**的哪一级。按 Agent 使用的直接程度排列如下：

1. **文件内步骤**是首要层级：Agent 按顺序做什么。
2. **文件内参考**按需查阅。若同级规则本就平行（review 的所有规则位于同一层），平铺完全合理，不是坏味道。
3. **披露式参考**移到单独文件，通过上下文指针访问，仅当指针触发才加载。可以是同目录的兄弟文件，也可以是任何文档能指向的外部材料。

下沉得太少会使顶部臃肿，太多则会隐藏 Agent 真正需要的内容。这种张力就是决策本身。

**渐进披露**是沿阶梯向下移动（从主文件移出，置于指针背后），让顶部保持易读。这不主要是 Token 优化，而是保护信息层级。分支是最清晰的判断方法：每个分支都需要的内容放内联，仅部分分支需要的内容放在指针背后。当文档包含步骤时，本应披露却留在文件内的参考会掩盖步骤，让 Agent 是否注意到步骤变得随机：这是执行差异的杠杆，不只是易读性问题。

**就近放置**是文件内的配套原则：层级决定一段内容*下沉到哪里*，就近放置决定抵达后*它挨着什么*。一个概念的定义、规则、注意事项应置于同一标题下，而不是散落各处，这样阅读一部分便能看到其相邻内容。判断标准：文档读起来应像专为 Agent 编写的文档。成组的材料符合这个标准，散落的则不符合。（这与重复不同：重复是在两处写相同含义；散落是在多处拆开同一含义。）

**蔓延**是另一种失败模式：即使每一行都有用且不重复，文档仍可能长得过头。冗长稀释注意力，每多一行都增加保持内容有效的负担。解法是利用层级：将参考移至指针背后，按分支或执行顺序拆开，让每条路径只携带自己需要的内容。

## 步骤与完成条件

每个步骤都以一个**完成条件**收尾，明确 Agent 何时完成任务。它通过两个属性发挥作用：

- **清晰度**：Agent 能否判断已完成与未完成？模糊的边界（“理解充分”）会诱发**过早完成**：尚未真正完成，就把注意力转向*结束*。后续仍可见的步骤（**完成后步骤**）产生催促作用，而完成条件的清晰度提供抵抗。依次防御：**先明确边界**（局部且成本低）；只有边界不可避免地模糊、*并且*实际观察到抢跑时，才通过拆分序列隐藏后续步骤。隐藏仅在真实的上下文边界上有效（交接或派发 subagent）；内联调用仍会保留后续步骤，无法清空上下文。
- **要求力度**：条件要求完成多少。“逐一说明每个修改过的模型”能迫使充分工作，而“生成变更清单”不能。要求力度驱动**实地工作**（Agent 在步骤中做的调查，隐含在措辞中，不必写成独立步骤），而且不限于步骤：“应用每条规则”约束平铺的参考正文，与“完成每个步骤”约束序列相同，因此纯参考文档也能设定全面性要求。

最强的条件既可检查，又覆盖全面。

## 何时拆分

把一篇文档拆为两篇会增加上述两类负担之一，因此只有拆分物有所值时才进行：

- **按顺序**：当后续步骤容易让 Agent 急于结束当前步骤时，拆分步骤序列。让后续步骤暂时不可见，可以推动当前任务更多实地工作。注意反面：合并序列会让每个步骤看见后面的步骤，诱发过早完成。
- **按调用方式**：Skill 特有规则，参见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词

**引导词**是模型预训练中已有、Agent 执行文档时用来思考的简短概念（如 *lesson*、*fog of war*、*tracer bullets*）。重复的是这个词，而不是整句话；它以最少 Token 逐渐锚定一片行为，调用模型已有的先验知识。新造词若定义清楚也能用，但没有预训练先验，解释成本会抵消已有词的优势；优先选择已有概念。

它在两处发挥作用。在正文中锚定*执行*：每次看到相同词，Agent 就调用相同行为；在平铺的参考中，词语使注意力集中在某类事项上。在指针中锚定*调用*：当你的提示、文档、代码库使用同一个词，Agent 会更可靠地把共享语言与材料联系起来并访问它。

寻找用引导词重构的机会。例如在三处都展开描述的三元组、花一整句话暗示一个概念的指针。都可以压缩成一个 Token：

- “快速、确定性、低开销” → *tight*（*tight* loop，紧凑循环）。
- “你相信有效的循环” → *red*（红灯），将模糊关卡变成可观察的二元状态（循环针对 bug 变红，或没有变红）。

收益有两重：Token 更少，Agent 思考时的抓手更清晰。假设每份文档都有可用引导词替代的重复阐述，然后去寻找它们。

**否定句**是这项杠杆旁的失败模式：用禁止行为来引导，会将被禁止的行为带进上下文，使之*更*容易出现，而不是减少。说“不要想大象”，脑中就只有大象；否定词很弱，激活的概念很强，禁令容易被半读成执行指令。用**正面表述**：直接说明目标行为（“写单行注释”），避免提及被禁止的行为。只有无法正面表述的硬性护栏才值得写禁令；即使如此，也要配合正面目标，让注意力落在该做的事上。

## 删减

- 每种含义只保留**单一事实来源**：一个权威位置，让改变行为只需修改一处。**重复**（多处重复同一含义）增加维护成本和 Token，还把一种含义在层级上的显著性抬高到不合理位置。（与有意重复*一个词*而非含义的引导词相反。）
- **环境**本身也是事实来源（`package.json` 脚本、配置文件、目录布局、`--help` 输出）；重述环境的文档是一份**缓存**，只有查询本身昂贵才值得占用负担。缓存 Agent 通过查看环境无法发现的信息：未成文的约定、决策原因、配置无法透露的陷阱。单文件、单命令就能获取的信息应留在环境中，避免文档过期。
- 检查每一行的**相关性**：它是否仍与文档任务相关？一行内容可能从未与任务有关（纯背景介绍或本该披露的分支），也可能因行为或外部世界变化而过期。短文档更容易维护相关性。缺少删减纪律时，默认结果是**沉积**：因为增加内容令人安心、删除内容让人不安，陈旧内容层层堆积，最后需要挖开才能找到仍有效的部分。
- 逐句寻找**无效指令**：模型默认就会遵循的指令却仍占据上下文。判断标准（相对默认是否改变行为）取决于模型，而不是读者：两人对一条指令是否无效意见不同，本质是在争论默认行为，应通过执行文档而不是辩论解决。无效时删掉整句话，不只是删几个字。这个测试也衡量引导词：弱到不能超越默认行为的词（Agent 本就大致认真时说“认真些”）是无效指令；应换用更有力的词（如“锲而不舍”），而不是换一种技术。
